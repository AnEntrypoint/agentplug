# AGENTS.md

AgentPlug is gm's native WebAssembly host: the `agentplug-runner` daemon and `agentplug-host` imports. Work on `main` as GitHub user `lanmower`.

## Source and release boundaries

- Code is self-explanatory. No comments except Rust `// SAFETY:` justifications; keep language attributes and shell shebangs. Non-derivable operational contracts go here or in user docs.
- A push to `main` runs `.github/workflows/release.yml`: bumps the patch version, builds every runner target, publishes the release daemons consume. Never install, copy or execute a local source-built runner as an update path.
- Runner and plugin updates install only bytes whose sha256 matches the published `.sha256` sidecar. The locally-built-runner guard, version monotonicity and the SHA-256 check are independent; never weaken one to repair another.
- Build provenance watches Git-resolved HEAD, every symbolic ref and packed refs across submodule and worktree gitdirs. Missing loose refs watch their nearest existing parent. Ordinary commits refresh embedded COMMIT without touching source or clearing Cargo caches.
- Canonical runner promotion rechecks the local-build guard before replacing the installed binary and re-execs from the canonical path. A refused promotion keeps the staged daemon serving.
- A discovered same-user GitHub CLI credential directory is shared with Git, execution children and updater API calls; fresh boot, takeover and re-exec discover it before workers start. Inherited `GH_CONFIG_DIR` wins. Git uses transient `gh auth git-credential`. The updater keeps the `GITHUB_TOKEN.or_else(GH_TOKEN)` selector: an empty value falls back to `gh auth token`, not the other name. CLI retrieval is noninteractive (5 s deadline, 8 KiB cap); its memory-only cache keeps successes 60 s and misses 10 s, keyed by PATH, directory and cwd for relative PATH entries. CLI 401 invalidates it and in-flight refreshes; explicit-token 401 never rescues through CLI. Never export tokens or expose them in files or output.
- Execution children inherit explicit `SHELL` and `XDG_RUNTIME_DIR`. On Unix, an absent `SHELL` selects the effective user's account shell only when absolute, executable, root/user-owned, and not group/other-writable. One cached login probe captures only `PATH` and `XDG_RUNTIME_DIR`, bounded to five seconds and 64 KiB; an absent runtime directory is filled only from that probe. Never guess a runtime directory or forward the login shell's wider environment.

## Runtime invariants

- The dream cycle trigger ticks every 60 s (`DREAM_RSI_CYCLE_TICK_INTERVAL_MS`, `spawn_dream_rsi_cycle_ticker` in `crates/agentplug-runner/src/daemon.rs`). Queueing needs 20 new observations (`MIN_NEW_OBSERVATIONS`) and 15 min since the owner's last cycle reply or deferral (`COOLDOWN_MS`, `crates/agentplug-runner/src/dream_cycle.rs`).
- Dream observation maintenance queues only registered `dream-replay-cycle` for the actual owner, keyed by canonical `session_id`. Private atomic per-owner state persists before its fixed pending request is published; recover that same request and never advance the dispatch cursor on queueing or deferred/failed replies. Accept acknowledgments only after the input/claim is gone, from a matching owner/cycle response with new verified replay evidence. Dispatch IDs are compared for equality, not ordered. Missing cursors in the capped window mean partial coverage, not exact counts. Replies and observations are bounded to 1 MiB; each walk phase (changed owners, then the cursor resume) processes at most 64 entries under its own cooperative 50 ms budget, so a busy changed-owner phase cannot starve the resume. Rotate roots after eight entries; keep at most 256 root cursors and remove deregistered roots. Cache pressure defers discovery and never proves complete coverage. Retries have a durable 15-minute cooldown; maintenance never evaluates or deploys policies.
- `host_fs_readdir` returns zero on directory or entry-read failure, never a successful empty or partial array. Structural indexing propagates that failure and refuses pruning or graph evidence; legacy guest wrappers may explicitly keep their empty-list fallback.
- `host_fs_read` reserves packed value `1` for a successful empty UTF-8 read, without allocation. Actual path, I/O and UTF-8 failures remain `0`; nonempty reads keep their pointer/length ABI. Guests must recognize the empty marker before decoding a pointer; older guests still refuse it.
- Spawn and JavaScript adoption share process-instance checked monotonic IDs and never overwrite occupied entries. Failed registration cleans up only the newly owned child and process group. Task output checks the live registry first, then its private durable result store; missing handles distinguish registry-instance mismatch from a missing current-instance task. Adopted tasks expose raw captured streams, without decoding foreground JavaScript result frames.
- Runner handoff acquires execution admission before preserving completed results; active execution, children, or pipe drains defer it. Acquire shared admission before a child can execute and keep it through registration/adoption. Failed preparation or ownership transfer releases admission; successful transfer closes it before the old host can start another child.
- Completed results keep the last 64 KiB of each stream with explicit omitted-byte counts for 30 minutes after child exit. Private schema-checked atomic records are bounded to 1 MiB each, 512 entries and 64 MiB total; directory scans stop at 1024 entries or five seconds. Expiry and explicit task-stop remove records; full or invalid stores refuse handoff without evicting unexpired results. Default task-list does not persist; explicit `prepare_handoff:true` uses the production preparation function and releases its guard without transferring ownership. New and loaded records share validation; reversed wall-clock timestamps refuse preservation. Unix result directories/files must be private and effective-user-owned. `libc::geteuid` has no pointer inputs or failure mode; record reads reject symlinks with `O_NOFOLLOW`.
- The spool daemon is a singleton per project. Requests are written atomically, claimed by rename, and identified by `(verb, session-id-task-number)`; preserve those properties when changing dispatch or recovery.
- Dispatch concurrency is intentionally lane-based: read-only work stays parallel while state, store and Git mutations serialize only against their own lane. A claimed request must always produce an out-file or be released for recovery.
- Kill only processes owned by this host.
- Every subprocess has a bounded wall-clock deadline and tree cleanup. Keep stdout/stderr draining concurrent with child execution; keep oversized dispatch results in a spill file, not an unbounded JSON reply.
- Foreground execution waits at most 50 ms for both output drains after child exit, capped by the remaining execution deadline. Unfinished readers transfer to task ownership; they do not prove a descendant holds a pipe.
- Foreground default JavaScript results use the last sentinel candidate followed by a complete JSON line; remove only that validated frame. Sentinel text inside returned strings or ordinary stdout stays data, including when stdout has no preceding newline.
- Plugin reload recovery receives the current engine and module map at dispatch construction. Nested calls reload registered empty sibling pools from that module map after shared-store eviction; populated or busy pools keep their owners. Failed reloads remain failures, not indexed evidence. If poisoned-store recovery fails, capture the active module map and instantiation error before changing registry behavior.
- The `gm` pool defaults to 8 slots (`DEFAULT_GM_POOL_SIZE`, capped by host parallelism and `MAX_GM_POOL_SIZE`; `gm_pool_size` in `daemon-config.json` overrides). A dispatch holds one slot for its whole run, including a long `exec_js`, so pool size bounds how many slow dispatches run before a quick one waits. Heavy verbs stay capped at `MAX_CONCURRENT_HEAVY_DISPATCHES` (3) slots.
- The claim pass is the daemon main loop: synchronous work there delays every queued dispatch. Measured with 128 roots of 139 empty verb dirs, claim p50 fell 15 s to 2.1 s (p95 28 s to 6.0 s). Fixed causes: per-entry `git rev-parse --show-toplevel` (now `cached_project_root`, 10 min TTL); inline browser sweep and update polls (now a housekeeping thread and the `update-poll` worker); per-pass re-reads of empty verb dirs (now one `stat` while mtime is unchanged for 2 s). A new synchronous call in the main loop needs the same measurement.
- `browser_lease_acquire` waits up to `browser_lease::WAIT_MS` (600 s) on a foreign holder, so `dispatch_project` answers lease verbs on their own thread; inline, one wait stalled every project's claims (reproduced 2026-10-18 with a foreign `owner.json`). `spawn_claim_sweep_stall_watchdog` is the backstop: when `mark_main_loop_phase` has not advanced for `claim_sweep_stall_secs` (default 300, x3 while a plugin compiles) and a leased root holds a settled request that old with claim slots free, it logs the stuck phase and exits 71 so the guard restarts the daemon and the boot sweep re-queues orphaned claims.
- Every Windows child spawn in `agentplug` goes through `windowless::apply_windowless`; `agentplug-runner` calls `ensure_hidden_console()` first. `CREATE_NO_WINDOW` alone leaves each console child (git, node, powershell) console-less, so its own children allocate and flash a conhost. A runner-owned hidden console is inherited by the whole subtree; `apply_windowless` falls back to `CREATE_NO_WINDOW` only when no console exists. Source: `agentplug/crates/agentplug-host/src/windowless.rs`.

## Configuration and compatibility

- `.agentplug/plugins.json` declares download specs; `.agentplug/plugins.txt` declares loaded plugins. A project declaration overrides built-ins of the same name.
- Do not add tracked long generated paths: the Windows release checkout has a practical path-length limit. `.agentplug-kv` is runtime index state and must not be committed.

## agentplug-host: contracts moved from source comments

- Child ledger (`child_pids.rs`): each spawn appends one unlocked JSON line to `<root>/.gm/exec-spool/.child-pids.jsonl`, shared with `gm-mcp/src/child-ledger.js`. Rotates to `.jsonl.1` above 1 MiB. An unclaimed pid is never a reaping candidate; `exec_js` records the pid before any step that can fail.
- Redirects (`build_agent_without_redirects`): 3xx replies go back to the caller, so each hop can refuse a private address.
- Timeouts (`http_agent.rs`): the shared API agent uses 10 s. The download agent uses 900 s: a 14 MB release binary must finish within it on a slow link.
- Watcher log (`watcher_log.rs`): rotates at 10 MiB, keeps 2 generations (oldest first) before each append; a rotation failure never drops the appended line.
- Runner console (`windowless.rs`): `ensure_hidden_console` is a no-op on purpose. Windows Terminal hosts every console and SW_HIDE does not hide its tab, so an allocated runner console opened a visible tab on each start. Children get CREATE_NO_WINDOW from `apply_windowless`.
- Job objects (`process_tree.rs`): members outlive the job handle. `terminate_job` is the only path that kills through the job.
- Precompiled artifacts (`precompiled.rs`): a compiled artifact is a pure function of the wasm bytes and the engine compatibility hash, so one copy serves every install dir. Publishing hard-links it into the system dir and re-points the local name at those bytes. Hard links are safe because writers stage a sibling and rename it over the path, never writing in place; superseded artifacts are unlinked. A failed step leaves the local artifact, so loads still succeed. Before this rule, bert took 4051 ms and 73 MB per install dir.
- Browser body grammar (`browser.rs`, `parse_cdp_browser_body`): an optional first non-blank line `engine=cdp`. Every other non-blank line not starting with `#` is one step, split on the first whitespace, so `wait 500` and `cdp Page.navigate` read alike. `cdp <Domain.method>` takes JSON params on the following line; omitting it sends no params. `events <Domain.event> [where <field>~<value>] [limit=N]` captures events from the moment the call attaches. The tool-step list is `TOOL_STEP_GRAMMAR`.
- Browser profile marker: the gm-owned browser Chrome is closed by a match on its profile path in the command line. User Chrome never carries that path.
- `run_helper`: the Node CDP helper is fed on stdin and receives its config in `GM_BROWSER_CONFIG`. The child is killed when the budget runs out.
- `browser_cdp`: headful Chrome over CDP on the single browser shared by a project root. The call holds the lease and releases it on return; Chrome stays open (see Browser lease). The helper reuses the project's existing page and creates one only when none exists.
- `browser_cdp.mjs` (concatenated after `browser_cdp_tools.mjs`, run as `node --input-type=module` on stdin): config JSON in `GM_BROWSER_CONFIG` has the shape `{ port, targetId?, cwd?, session?: {name, file}, steps, pageTimeoutMs, textLimit }`. A session keeps its tab and uid map across calls; its file is written atomically. The helper prints one JSON object and exits 0 when every step ran.
- Browser lease (`browser_lease.rs`): holders restamp `heartbeatAt` every 2 s (`HEARTBEAT_MS`); a heartbeat older than 120 s (`TTL_MS`) means dead, whatever its pid says, on every OS. Acquire waits up to 600 s (`WAIT_MS`). `create_new` on `owner.json` makes claims exclusive. An unreadable claim file belongs to a peer still writing it for 5 s (`CLAIM_CREATE_GRACE_MS`), so it is not dead. Takeover kills the named holder, reaps browsers on the profile and unlinks the claim; release removes only the caller's claim, ends the lease and keeps the shared Chrome open. It closes after 15 min with no holder and no waiter (`BROWSER_IDLE_CLOSE_MS`, env `GM_BROWSER_IDLE_MS`); the idle timer restarts on every acquire and release. Housekeeping every 30 s closes exited, idle-expired and lost-claim browsers. A runner handoff keeps an idle browser: shutdown leaves it running when no holder or waiter is present and writes `session/browser.json` (port, pid, idle clock), and the successor adopts it on the next acquire while its window runs. A busy browser is closed at shutdown. Open, close and exit events append to `<root>/.gm/exec-spool/.watcher.log` with the root, the Chrome pid (not the `/usr/bin/chromium` shell launcher, logged as `launcher_pid`), the runner pid and a reason: `browser-idle-close`, `browser-exited` (with the launcher's exit status), `browser-closed` (`not-running`, `headful-mismatch` or `runner-shutdown`), or `browser-lease-lost`. Session dir: `.gm/browser-lease/session` per root. Verbs `browser_lease_acquire`, `_release`, `_status` take `{root, agent, ttl_ms, wait_ms}`; `root` defaults to the dispatch root, `agent` is required for acquire and release.
- `exec_js` SAFETY notes (no clippy lint enforces them): the passwd buffer stays live until the shell bytes are copied, and only the effective UID is queried. `fcntl` changes only read-side status flags of the owned pipe, and `O_NONBLOCK` is a valid status flag.
- `exec_js` module split: top-level `import` and `export` declarations are lifted from a stdin body, so the body runs with `--input-type=module`. A CommonJS body has an empty head and runs byte-identically. `require`, `module.exports` and `exports.x` never match, and dynamic `import(...)` is untouched. Comments and string bodies are skipped. A declaration ends at the first `;` or newline at bracket depth 0.
- Agent exec (`agent` and `claude` langs): the code is the prompt for a headless Claude Code agent, so a subagent with no host Agent tool can start its successor. Print mode cannot answer permission prompts, so the default permission mode is `DEFAULT_AGENT_PERMISSION_MODE` (`bypassPermissions`), matching the ungated exec surface.
- Login PATH: the first exec probes the login shell (cached, 5 s cap); tests warm that cache before timing.
- Git memo (`imports.rs`): layout questions (`rev-parse --show-toplevel` and siblings) are answered once per (directory, question) and forgotten after a layout-moving git command runs in an overlapping directory. Flags outside the list (`status --porcelain`, `hash-object`, gating `ls-files`) always reach git. An answer guarded by a file identity is dropped by that identity alone. The `ls-files --stage` answer holds while index mtime and length are unchanged. HEAD is read from disk when a loose symref; packed refs, symref chains and unreadable `.git` fall through to git. Listings above 1 MiB are not memoized. Stats flush every 60 s and count asked vs reached.
- Durable rename: the tmp file and its parent directory are both synced. Without both syncs, a crash can leave the old or empty target while success is reported.
- Admission hold (`registry.rs`, bound `ADMISSION_HOLD_MAX_MS_DEFAULT` = 60 s, env `AGENTPLUG_ADMISSION_HOLD_MAX_MS`): a counter is a lease, not a grant for the dispatch's life. A waiter reclaims the oldest general-band counter older than the bound, only while a physical slot is free. Reclaim returns the counter and does not stop the holder. `release_holder` returns false for an unknown id, so a reclaimed guard cannot release twice.
- `git_band_admission_limit` uses `.max(1)`: at POOL_SIZE 4, `1 - 1` admitted nobody. One git slot is intended.
- `admission_holds` lists counters with their age, beside `lane_holds`.
- `acquire_slot_until`: past `give_up_at` the ticket is abandoned, the FIFO skips it, and the caller answers admission-starved.
- Admission ordering: a dispatch takes a plugin slot first and admission second. If admission is refused, it hands the plugin slot back and requeues. Waiting for a plugin slot while admitted wedges the gate; waiting for admission while holding a slot takes the slot reserved for short verbs. `SLOT_HELD_ADMISSION_WAIT_MS` (250 ms) is that brief wait; the gate does not count waiting dispatches.
- `release_admission_for_thread`: a dispatch calls it after writing its result. Normal unwinding already released the guards, so it is a no-op. A thread that died holding a slot leaves no guard, and that slot would starve later dispatches.
- Plugin recovery: `RememberedPluginModule` lets a refill rebuild an evicted slot in place when the module map transiently lacks the plugin during a wasm recompile.
- `note_pending_eviction_consumed` counts owed evictions; the entry disappears when the last one is paid.
- Evicted-slot refill: a run that hit the call deadline is not repeated, because a second identical run would spend the budget again and hold the slot.
- Git network lane (`GIT_NETWORK_LANE_VERBS`: `git_push`, `git_pull`, `git_fetch`): the remote sets hold time (minutes, not seconds). They stay on the git lane (one writer per worktree) and yield to checkout-bound claims queued behind them after `LANE_NETWORK_YIELD_MS` (120 s, env `AGENTPLUG_LANE_NETWORK_YIELD_MS`) of their own waiting.
- Lane queue (`LaneWaiter`): FIFO by claim age. Identity is the verb plus a body hash, stable across re-dispatch while the spool mints fresh task ids; a re-dispatch reclaims its parked token. An entry is dropped when its dispatch gets the lane, or by TTL (`LANE_TICKET_TTL_MS`, 600 s) on `last_seen_ms`. `claimed_ms` is never refreshed, so it bounds the network yield. `active` is true inside `acquire_within`. A place is inherited only from a parked ticket, so byte-identical bodies from different callers get one ticket each.
- `LANE_TICKET_STALE_MS` (30 s): a waiter not re-claimed in that window stops contending, and the lane passes on. `lane_queue_depth` counts active and recently re-dispatched claims as contending. Parked remainders are reported as stale; they are neither added nor dropped.
- `lane_admissible` runs under the owner lock, so the head cannot change between check and insert. A claim ahead that stopped contending does not block. A network-bound claim ahead is outranked by a checkout-bound claim only before its own yield window ends.
- `requeue_lane_claimer_front`: a displaced holder (taken by the hold watchdog) is parked back at the head with its identity, because it never ran and is owed its place.
- `GmFairnessGuard::still_owns`: a stuck holder that lost the lane checks this before dispatching and answers starved, so it never touches the worktree.
- Lane release: `release_abandoned_lane_owners` frees lanes whose project root is no longer live. `release_dead_lane_owners` frees lanes whose one holder the caller reports as not live. A holder with an unknown verb or task is never reaped. The owning dispatch keeps running; its guard finds a different token on drop and leaves the new owner alone.
- `lane_holds` is a watchdog read. It never releases a live holder, because one writer per lane keeps the index consistent. `lane_waiter_count` lets the watchdog spend that property only when someone is waiting.
- `UNSERIALIZED_STORE_WRITER_VERBS` (`codeinsight`, `callers`, `callees`, `impact`) run outside the store lane by design, so a `callers` question never queues behind an index pass. They must still claim `.gm/gm.db.lock.owner`, because the store liveness rule treats a lock with no owner record as having no live writer. `dispatch_claims_store_owner` is the ownership predicate.
- `fs_write` is not on the state lane. Each write is a per-path mutex plus an atomic temp-file rename (`atomic_write_locked`), so writes cannot interleave on one path.
- `LaneQueueState.lane_position` is 1-based and counts only waiting dispatchers. It is read through `.dispatch-wait.json`. Lock order is owners, then waiters.
- Lane yield class: git-network verbs are class 0 and every other verb is class 1. Only the relative order inside one lane matters.

## agentplug-runner comment sweep

Moved from crates/agentplug-runner source comments (checked against source at 15c2ad21). Each bullet is a fact code does not state.

### Daemon guard (src/daemon.rs)
- One install dir = one daemon + one daemon-guard. Two guards shred each other's claims: the orphan sweep answers `dispatch_orphaned` for the other's live work.
- Identity: `install_dir()/daemon-guard.lock` is a bare integer pid (older builds must still refuse a second guard); `install_dir()/daemon-guard.owner.json` holds pid, exe, version, install_dir and heartbeat ts. New builds read both.
- Lock reclaim, per record. Guard lock (`daemon-guard.lock`): a dead pid is always reclaimable. A live pid is reclaimed when the owner record (`daemon-guard.owner.json`) is older than `GUARD_HEARTBEAT_STALE_MS`, or when that record is missing or names another pid and the lock is older than `GUARD_CLAIM_GRACE_MS`. Daemon owner (`daemon-owner.lock`, `claim_ownership`): a live pid is taken over only when the `daemon-status.json` heartbeat is older than `DAEMON_STALE_MS`. Proof, not seniority: a build that never writes an owner record is superseded after the claim grace.
- A guard never kills its daemon. It writes a stop marker that the daemon honours on its own loop, and retires after a grace if unhonoured. The marker stays in place: deleting it lets another guard restart a daemon that just retired.
- Stand-down: no fresh daemon heartbeat for the stale bound; or, for an `AGENTPLUG_HOME` override only (never the shared default home), `active_projects` 0 for the bound.
- Disuse is checked before freshness, since a live daemon heartbeats every poll. A surplus guard re-checks lock ownership every poll and retires if it lost it. Only the owning daemon arms its watcher.
- A stop is honoured only after the daemon's own quiet period.
- Handoff: a ready successor waits for an idle tick up to `TAKEOVER_FORCE_HANDOFF_AFTER_MS` (or `--force`), then forces the handoff and re-queues in-flight work. That bound must stay below `TAKEOVER_READY_MAX_AGE_MS`. A backoff defers the handoff without forgiving the starve clock. Starved drain runs in-flight work to completion; nothing is abandoned.

### Downloads and retention (src/download.rs)
- Backup retention orders by mtime over each asset family's sibling set, never by name pattern. Families are discovered from the directory. Kept: newest backups, the live asset, `.prev`, one in-flight staged copy; the newest backup survives even above the byte ceiling.
- Never deleted: current-state siblings (version and checksum markers, `<stem>.*.json` sidecars, staged copies, `.prev`, pinned copy), the running image (unlinkable on Windows while mapped), the canonical install path.
- Retention scans every install root and its plugin subdirectory, not only `install_dir()`.
- Retired `wasi-fs/<instance>` trees are removed by age only (`WASI_FS_RETAIN_AGE`): each is a derived copy of the project's `.gm/gm.db`. Entries that cannot be deleted (mounted; Windows refuses) are reported, not counted. An unreadable mtime keeps the entry.
- Shared payload cache keyed by sha256 (the release `.wasm.sha256` sidecar is the identity): one copy per hash under the real home, never `install_dir()`. Each home's `plugins/<name>.wasm` is a hard link to it, with copy as fallback. A hit is served only after its bytes re-hash. Entries unused past their bound are removed; live links keep their data.
- No writer mutates `plugins/<name>.wasm` in place: writes and rollbacks use temp plus rename (`write_download_atomically`, `record_plugin_load_failure_and_rollback`), so a shared inode is replaced, never written through.
- Staged names are `<exe>.new` or `<exe>.new2`; any staged suffix is stripped first, so a copy is overwritten, not chained.
- A junction or symlink to an installed skill means the source tree is the install; its SKILL.md is never overwritten.
- `source-head` in the release body names the commit recorded in `plugins/<name>.build.json`. A failure there never fails an install.
- A version file with a UTF-8 BOM is stripped before any semver compare.

### Claim dispatch (src/daemon/claim_dispatch.rs)
- A caller's `timeout_seconds` is a poll budget, not cancellation. A starved dispatch never ran, so `re_dispatch_safe` holds at any budget.
- Lane wait: `_agentplug_lane_wait_ms` (`LANE_WAIT_MS_BODY_KEY`, written by gm-mcp) or `lane_wait_ms` (public spelling) is removed byte-exactly before the body is hashed or reaches a plugin. Floor `LANE_WAIT_FLOOR_MS`. The default is short; the ceiling is separate, so a named budget buys the ceiling. The git lane always waits its full maximum.
- Lane holds are released only when: the holder is gone; stuck before `Running` past `LANE_HOLD_STUCK_MIN_MS`; running past `LANE_HOLD_RUNNING_MAX_MS_DEFAULT` with waiters queued; or it reached `Running` but has no registered worker past the stuck bound. A live running holder with no waiters keeps the lane. A displaced holder answers starved after `still_owns()` fails, so it never reaches the worktree. A worker-gone release is marked abandoned and its `Running` stage dropped, so the orphan sweep answers the claim.
- Lanes are FIFO per (verb, body) identity: a re-dispatch under a new task id keeps its queue position.
- Checkout-bound claims (commit) yield ahead of network-bound ones (push) until the push passes its yield budget. One writer per worktree always holds.
- Claim heartbeat: `ClaimHeartbeat` renews the `claim-live` marker every `CLAIM_HEARTBEAT_MS` from thread start (lane wait included) until return. A marker older than `CLAIM_HEARTBEAT_STALE_MS` means the owner is gone. The marker is removed with its claim and joined, never detached.
- A dispatch-wait ledger row keeps a claim alive only until `ORPHAN_CLAIM_MAX_AGE_MS`, unless the owner keeps beating its marker. `LEDGER_UNOWNED_STATES` name no owner and never protect a claim. A foreign daemon's live row does.
- Host-built receipts get a dispatch id of shape `<ts>-<seq>-<hash>`, hashed with the plugin ledger's algorithm; ledger write is best-effort. Bodies above 1 MiB are not re-parsed.
- Store lock `<db>.lock` is abandoned when it has no `.owner` record, a dead owner pid, or a heartbeat older than `STORE_LOCK_STALE_MS`. Only the owner removes a live lock. Unserialized codeinsight writers claim the owner record but never settle the lock.
- The dispatch ledger holds `DISPATCH_LEDGER_MAX_ENTRIES` rows and is rewritten only on change.
- Out-files are kept `SPOOL_OUT_WITNESS_HORIZON_MS` after write; above `SPOOL_OUT_HARD_MAX_FILES` the oldest are trimmed.
- A `wait`/`sleep` whose duration has elapsed settles as completed, or timed_out if it asked for longer than served.
- The admission band that refuses a dispatch is listed as `admission_hold_max_ms` in the status, not only the lane holds.

### Selfcheck (src/main.rs)
- Selfchecks are live witnesses against the real guard (lane FIFO and yield, budget, hold release, abandoned lanes, `catch_unwind`, pool size 4). Per-call env overrides for hold, ceiling and yield bounds exist only so selfchecks do not wait minutes.
